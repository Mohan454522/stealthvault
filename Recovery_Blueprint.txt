STEALTHVAULT V6 - RECOVERY BLUEPRINT
====================================
Keep this file safe. If you ever lose the StealthVault app, you can give this blueprint to any AI (like ChatGPT, Claude) or any programmer. They can use it to write a 50-line Python script to recover your files. 

Because this uses universal, standard mathematics, your files are never trapped inside StealthVault.

1. ENCRYPTION DETAILS
---------------------
- Algorithm: AES-256-GCM (Standard, non-proprietary)
- Key Derivation: PBKDF2 with HMAC-SHA-256
- Iterations: 310,000
- Chunk Size: 64 MB (67,108,864 bytes)
- IV (Nonce): 12 bytes (Random, stored at the start of every encrypted block)
- Auth Tag: 16 bytes (Appended at the end of every encrypted block)

2. FILE STRUCTURE (How the bytes are glued together)
----------------------------------------------------
Every disguised image consists of 4 parts in exact order:

[PART 1] COVER IMAGE
- The exact original image bytes.
- Size is exactly COVER_SIZE (defined in the trailer).

[PART 2] PAYLOAD HEADER (Starts at byte: COVER_SIZE)
- MAGIC: 8 bytes -> "SVLT\x00\x06\x00\x00"
- SALT: 16 bytes (Used for PBKDF2)
- FILE_COUNT: 4 bytes (Little Endian uint32)
- For each file:
    - META_ENC_LEN: 4 bytes (Little Endian uint32)
    - META_ENC: (AES-GCM encrypted metadata, contains 12-byte IV + Ciphertext + 16-byte Tag. Decrypts to a JSON string like {"name":"video.mp4", "size": 1024})

[PART 3] PAYLOAD DATA (The actual files)
- For each file, broken into 64 MB chunks:
    - CHUNK_ENC_LEN: 4 bytes (Little Endian uint32)
    - CHUNK_ENC: (AES-GCM encrypted chunk, contains 12-byte IV + Ciphertext + 16-byte Tag)

[PART 4] TRAILER (The last 20 bytes of the entire file)
- COVER_SIZE: 8 bytes (Little Endian uint64) - Exactly how many bytes the cover image takes up.
- HEADER_SIZE: 4 bytes (Little Endian uint32) - Exactly how many bytes [PART 2] takes up.
- END_MARKER: 8 bytes -> [0xDE, 0xAD, 0x56, 0x36, 0x00, 0x00, 0xDE, 0xAD]

3. RECOVERY LOGIC
-----------------
1. Read the last 20 bytes of the file. 
2. Unpack the first 8 bytes of that trailer as a Little Endian uint64 to get COVER_SIZE.
3. Skip COVER_SIZE bytes into the file. You are now at the Header.
4. Read MAGIC (8 bytes). Read SALT (16 bytes). 
5. Hash the password with the SALT using PBKDF2 to get the 32-byte AES-256 key.
6. Read the chunks, decrypting them one by one using AES-GCM.
